Dense (Qwen3-32B)

What this measures. We hand a single prompt to vLLM (the rollout side), let it generate 128 tokens, and capture the per-token sampled-token logprob. The same (prompt + response) is then teacher-forced through the trainer-side reference (FSDP or Megatron in bf16) on the same L40S host. Each tile reports the mean ESS over the response — how usable that rollout would be for off-policy training. Green (ESS > 0.99) means the two engines agree token-for-token; lower values mean the trainer would need stronger off-policy correction or would have to drop the rollout. Columns are the rollout-side precision · device; rows are the trainer-side reference. Click any tile to drill into the per-run detail.

MoE (Qwen3-30B-A3B)

What this measures. Same recipe as the dense matrix, but instead of comparing logprobs we compare which experts each engine picked. vLLM emits the top-k MoE router decisions per (token, layer) via enable_return_routed_experts=True; the trainer-side reference (FSDP or Megatron) teacher-forces the same (prompt + response) with router hooks and captures its own choices. Each tile reports the mean router_flip_rate — fraction of (token, layer) cells where the engines' top-1 expert disagrees. Lower is better; the marketplace problem becomes visible above ~5% (amber): at that point ~5% of the gradient signal would land on the wrong expert without router-aware off-policy correction. Hermes Agent — Dense (Qwen3-32B)

What this measures. Real Nous Hermes Agent multi-turn trajectories against the same vLLM serves used by the dense + MoE matrices above. Each task in our 12-prompt suite is run once at bf16 (the trainer-equivalent reference), once at fp8 (the precision-shifted rollout), and a second time at bf16 with a different sampling seed (the noise floor). The left tile compares fp8-vs-bf16 — the load-bearing marketplace signal. The right tile compares bf16-vs-bf16-different-seed — what divergence we get from sampling alone, with no engine/precision change. The tile's headline metric is final_answer_match (k-of-12 tasks where rollout and trainer landed on the same final answer); the bar shows mean tool_call_jaccard. Green ≥80%, amber 50-80%, red <50%. If the precision-effect tile is materially more divergent than the noise-floor tile, fp8 inference changes what the agent actually does, not just its per-token logprobs.

Hermes Agent — MoE (Qwen3-30B-A3B)

Same recipe, MoE rollouts — with TP held constant. Hermes Agent trajectories over Qwen3-30B-A3B. The fp8 variant must run at TP=2 (FP8 block_n=128 / ffn_intermediate=768 constraint), so the precision-effect tile pairs vLLM-fp8 @ TP=2 against a fresh vLLM-bf16 @ TP=2 reference (apples-to-apples). The noise-floor tile compares bf16 @ TP=4 against itself with a different sampling seed — same engine, same precision, same TP, just different RNG. The MoE matrix above already shows fp8 adds 2-3% router_flip_rate at the token level; this section asks whether that compounds into different agent actions. At n=12 trajectories the TP-matched precision effect is essentially identical to the noise floor — at this sample size, fp8 doesn't move the dial above what sampling alone already does.
