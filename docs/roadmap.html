streams-rollout-market / open-source plan

Turn rollout generation into a safe, measurable market.

Agentic RL is bottlenecked by long, expensive, heterogeneous rollouts. The project goal is to let many workers generate trajectories while the trainer receives only versioned, token-level, budget-checked experience.

The problem

Rollouts are the scarce resource

In agentic RL, a single prompt can trigger long chains of model calls, tools, evaluators, retries, and context growth. More trainer GPUs do not help if useful groups arrive too slowly.

Asynchrony creates policy debt

Old policy versions, different inference engines, quantization, hardware kernels, and transport delays all mean the behavior policy is not the trainer policy.

GRPO needs group coherence

Sibling trajectories for the same prompt should come from one logical behavior policy. Mixing policies inside a group can corrupt advantage estimates.

Core idea

The product is the contract. The project should not begin as a full marketplace. It should begin as the open protocol that makes a future market possible: policy manifests, sample-group schemas, token-level integrity, worker heartbeats, budget metrics, and trainer-agnostic batch retrieval.

The key research hypothesis is a shared off-policyness budget: staleness, train-inference mismatch, quantization drift, device heterogeneity, and weight-transport latency are logged as measurable budget debt. The controller can use one operational guardrail while still preserving source-specific telemetry.

Roadmap timeline

Contracts - Week 1

Define schema, validation errors, sample lifecycle, and docs. Done when a minimal GRPO group can be validated and rejected with precise reasons.

Local async loop - Weeks 2-3

Local dispatcher, LiveStore, registry, mock worker, and mock trainer. Done when the trainer consumes groups without knowing worker or env endpoints.

Real inference adapter - Weeks 4-5

vLLM or SGLang adapter returning token IDs and logprobs. Done when OPBC logs real mismatch metrics.

Remote worker runtime - Weeks 6-7

Docker worker with heartbeat, policy pull, reload ACK, and signed sample submission. Done when a worker on a second machine contributes groups.

Budget controller - Weeks 8-9

Accept, correct, quarantine, or reject groups based on ESS, E[w^2], clipped fraction, lag, and contract validity.

Weight sync and quorum - Weeks 10-12

Full checkpoint sync first, patch transport second, k-of-n reload quorum third. Group pinning remains strict.

Benchmark release - Week 12+

Publish K-vs-L frontier, cross-engine/device mismatch matrix, trainer idle fraction, accepted tokens/sec/$, and quality metrics.

Research work packages

1. K-vs-L frontier

How stale can a rollout be as a function of token length, turn count, and task type?

2. Mismatch decomposition

Measure engine, precision, quantization, device, and staleness contributions one axis at a time.

3. Per-turn budget

Move beyond sequence-level IS for 50k+ token tool-using trajectories with tool-output masks.

4. Quorum reload

Replace global hard abort with routable worker quorums while preserving one behavior policy per group.

5. Patch transport

Evaluate full checkpoints, LoRA deltas, sparse patches, and quantized receivers under churn.

6. Verifiable rollout supply

Audit claims about policy version, tokenizer, logprobs, and environment receipts without trusting every worker.

One-sentence pitch

streams-rollout-market makes rollout generation a safe, measurable, and open supply layer for agentic RL: many workers, many environments, many inference backends, one coherent training loop.

Suggested license: Apache-2.0. Suggested initial audience: RL systems researchers, VeRL/ROLL/slime users, vLLM/SGLang adapter authors, decentralized compute providers, and agent benchmark builders.
