Open-source thesis

Cheap rollouts are useless unless they are trainable.

streams-rollout-market should launch as a rollout validity layer plus a public Mismatch Observatory: a way to show, measure, and control whether remote agentic trajectories still represent a usable behavior policy for policy-gradient training.

No trainerPolicy-pinned groupsOPBCMoE routing mismatchToken/logprob contracts

Decision

Proceed only if the project is more than a worker queue. A generic distributed rollout queue is useful but not a wow open-source project. A quality-scored rollout marketplace with token-level integrity, policy pinning, mismatch telemetry, and a public benchmark is a real wedge.

Why this place needs to exist

Rollouts starve trainers

Long, multi-turn, tool-using trajectories make rollout generation the bottleneck. More trainer GPUs do not help when accepted groups arrive too slowly.

Remote workers create policy debt

Stale weights, precision drift, tokenization drift, engine mismatch, quantization, MoE routing, and device differences all change the behavior policy.

The unit is not a token

The unit of supply is a verified trajectory group: same logical policy, token IDs, behavior logprobs, masks, policy version, engine fingerprint, and OPBC decision.

The architecture to show

External trainerPublishes policy versions; pulls accepted groups. No PPO/GRPO implementation in this repo.
PolicyRegistryVersion, checkpoint digest, tokenizer hash, precision and engine contract.
DispatcherRoutes jobs by policy lease, context length, device, cost, and reliability.
WorkersRun env + inference; return token IDs, sampled logprobs, rewards, traces.
OPBC + verifierTrain / replay / quarantine / reject with reasons.
LiveStoreTrainer-facing store of valid groups, not raw completions.

Policy-gradient materiality

Metrics

delta_t = log_pi_t - log_mu_t
log_ratio = sum(mask_t * delta_t)
w = exp(clip(log_ratio, -C, C))
ESS = (sum w)^2 / (n * sum w^2)

Decisions

A rollout is not accepted because it completed. It is accepted because its token IDs, behavior logprobs, masks, policy version, precision class, and mismatch budget make it usable by an external trainer.

Go / no-go

Go

Launch as the open rollout validity market: policy-pinned groups, OPBC, verifier, mismatch observatory, worker SDK, trainer client.

No-go

Do not spend serious effort on a generic queue, a payment layer, or a homegrown trainer. Those are not the wedge.
